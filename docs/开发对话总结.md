## 2. 2026-09-24 只读代码审查（v1.0.0 代码）

一次"只读审查 + 逐条核验"的组合：主会话 `session-edf4fbf7` 分 7 个模块（启动与生命周期、
单实例/平台、配置路径日志、目录解析与持久化、搜索筛选统计与开发时间、Tk 界面/异步/托盘、

全程禁止修改任何文件，探针脚本只写 `%TEMP%\ps_audit\`；用真实数据目录（当时还是
`C:\Users\<用户>\Downloads\<数据盘>`，129 项目 / 346 送样）做可复现验证。

**核验结论（重要，避免了照着错结论改代码）：**

- **推翻 2 条误报**：① 相对路径问题——PyInstaller 会把 spec 里的相对路径锚定到 **spec 所在目录**，
  与当前工作目录无关（证据：`PyInstaller/building/build_main.py` 的注释与 `api.py:_makeabs`）；
  ② matplotlib 的 Tk 后端由 **PyInstaller 自带 hook** 处理，不是 hooks-contrib 的功劳。
- **修正 1 条框架**：不是"两个版本源冲突"，而是**版本号从未进入构建**（exe 的
  FileVersion/ProductVersion/ProductName 全为空，实测确认）；真正被破坏的单一来源是**名称**——
  程序内部还叫「项目文件浏览器」（日志实证 `Starting 项目文件浏览器 1.0.0`），
  而 exe、托盘、README 都叫「项目统计」。
- **确认真问题 11 条**：写路径零容错（不可写目录会让程序在建窗口前就退出）、
  配置保存非原子、`.project_stats` 与 `%LOCALAPPDATA%` 的存储策略自相矛盾、
  `build.bat` 先删后建、便携版 zip 顶层没有包裹目录、托盘兜底图标 alpha=0（全透明，
  用户会以为程序消失了）、`EXE()` 未设 `exclude_binaries` 导致产物三份重复（单个交付物实占约 159 MB）等。

**当时列出的构建/发布问题**：无 `requirements.txt`、无测试、图标只有一张 32×32（而托盘请求 64）、
`README.md` 是 GBK 编码且描述了不存在的 `build.ps1` 与错误的 `dist/` 路径。

这一轮的成果是 `代码审查报告.md`；后来它与 `项目审查说明.md` 一起被合并清理成
`优化审查报告.md`（`项目审查说明.md` 的首要结论"封装正则会把 `ABC-MSOP8` 截断"实测为假，
原因是正则 alternation 的有序回溯，故未按其建议改动）。

### 3.1 性能与可靠性（v1.0.1）

- **启动 1317 ms → 205 ms**：把 `matplotlib` / `pyplot` / `mplcursors` 从模块顶层挪到
  `_load_chart_modules()`（统计图窗口里才导入）。其中 `import pyplot` 独占 634 ms；
  注意 `matplotlib.use("TkAgg")` 必须在 import pyplot 之前调用
- **主线程阻塞 361 ms → 0.3 ms**：工时基线扫描移到后台线程 `_configure_work_time_async()`，
  完成后 `after(0, …)` 回主线程刷新，并带过期保护
- 配置保存改**原子写**（临时文件 + `replace`），失败只记 warning
- 程序目录不可写时**回退 `%LOCALAPPDATA%\项目统计`**（`resolve_writable_dir()` / `get_data_dir()`）
- 单实例修正：删掉语义错误的 `ReleaseMutex`、第二个实例先 `CloseHandle`、
  互斥体名改成含安装路径哈希的 `Local\ProjectStats_<路径哈希>`；
  并且**单实例判定提前到建窗之前**，否则第二个实例会先读配置、先建 UI，甚至回写 `settings.json`
- 工时保存失败不再让计时线程静默停更：连续 3 次失败才停，且每次 `logger.exception`

### 3.2 解析准确性（v1.0.1）

  `(?!\d)` 规则挡掉（待确认）

- 更正一条早期错误结论：含「副本 / copy」的送样目录**本来就被正确排除**，
  原结论错在复核脚本用了 `re.search` 而非 `fullmatch`

### 5.2 卡片视图（v1.0.3）

关键实现决策：**整墙画在一张 Canvas 上，一张卡 = 1 个矩形 + 3 段文字**。
起因是控件版每张卡约 6.7 ms、几乎全是 Tk 逐控件文字测量，而且重建时"销毁旧卡"就占 553.8 ms。
实测对照（151 张卡）：

| 环节 | 控件版 | 画布版 |
| --- | --- | --- |
| 首次建墙 | 1222 ms | **190 ms** |
| 任一筛选 / 排序 | 300–800 ms | **16–92 ms** |
| 60 秒工时刷新 | ≈150 ms | **39 ms** |
| 切回卡片视图 | 407 ms | **129 ms** |

配套：视图切换（工具栏分段按钮 / 工具菜单 / `Ctrl+1`、`Ctrl+2`）、卡内展开详情
（真实 Frame 用 canvas window 摆进卡内，按实测高度撑高该行）、排序下拉、配置项
`view_mode`（老配置自动补默认值）、`WorkTimeService.get_project_seconds_bulk()`
（一次批量取工时，替代逐项目单查）、`tools\make_fixture_data.py`（生成合规样本数据）。

修掉的两个界面问题：展开卡里第三个按钮被截断（改成主操作占一行、两个次操作平分下一行）；
详情区高度算矮了压到下一行且浮在卡外（改成画进卡片内部并按实测高度撑高）。

  而 Segoe UI 没有中文字形，中文逐字回退导致同行字重、字宽、行高不齐；

## 6. 2026-09-30 "打开目录都打不开"：低完整性排查与修复 + 首次打包

用户报告：「打开目录、打开程序目录、双击打开表格这些都打不开路径了」——
三个入口点了既不报错也不打开。

**根因不在代码**：文件夹 `C:\Users\<用户>\Downloads\项目统计` 被 Windows 打了**低完整性标签**。
`icacls` 实测该项目目录及子项带 `Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)`，
而父目录 `Downloads` 和同级其他文件夹都没有标签——即只有这个文件夹受影响。
在该目录里启动的进程以 Low 完整性（S-1-16-4096）运行，于是：

- `subprocess.Popen(['explorer.exe', 路径])` 返回 `exit=3221225794`（`0xC0000142 STATUS_DLL_INIT_FAILED`），新窗口 0
- `ShellExecute` 返回 `ERROR_ACCESS_DENIED(5)`
- 顺带解释了另一条日志「新建项目目录 [WinError 5] 拒绝访问」——低完整性进程不能写数据盘 `J:\<数据盘>`

排查中排除的因素：不是 DSH 沙箱（用 WMI 在 agent 进程树之外启动同样失败）、
不是虚拟环境（系统 Python 与 venv Python 都失败）。

**修复**：`icacls "C:\Users\<用户>\Downloads\项目统计" /setintegritylevel (OI)(CI)M` 递归清除标签
（验证后 venv python 与 exe 都是 medium `0x2000`）；同时在程序里加自检——
新增 `runtime/integrity.py`（`is_low_integrity` / `describe_integrity` /
`LOW_INTEGRITY_CAUSE` / `LOW_INTEGRITY_FIX`），启动日志写明
`Process integrity: medium (0x2000)`，低完整性时额外 warning；
`_open_directory()` 改用 `os.path.normpath(os.path.abspath(...))` + `explorer.exe`
（比 `os.startfile` 更容忍中文/空格/历史混用斜杠），并在低完整性时提前拦截、说明原因。

修好后用 `cmd /c build.bat < nul` 打了包，产物 `portable\dist\项目统计\` 与
`portable\项目统计_便携版.zip`（43.9 MB、1283 项）——这就是 v1.0.5 二进制的实际来源。

## 8. 贯穿全程的经验

- **先备份再改**：用户两次明确要求，也形成了 `backups\项目统计_source_<阶段>_<时间戳>.zip` + MANIFEST 的习惯
