# 版本管理

本文档规定「项目统计」的版本号规则、发布流程与产物存档方式，并逐版记录发布内容。
变更明细见仓库根目录的 [`CHANGELOG.md`](../CHANGELOG.md)。

---

## 1. 版本号规则

`主版本.次版本.修订号`（语义化版本）：

| 位 | 什么时候加 | 例子 |
| --- | --- | --- |
| 主版本 | 不兼容的大改（数据格式、目录解析规则变更） | 1.x → 2.0 |
| 次版本 | 增加功能、界面改版 | 1.0 → 1.1 |
| 修订号 | 修 bug、性能优化、文档与工程调整 | 1.0.4 → 1.0.5 |

当前处于 **1.0.x**（同一套界面下的增量维护）。每次发版都必须同时更新：
`project_stats/app_info.py` 的 `APP_VERSION` 与 `APP_BUILD_DATE`、`CHANGELOG.md` 新增一节、
本文档第 6 节的版本记录表。

## 2. 版本号的唯一事实来源

```
project_stats/app_info.py
    APP_NAME       = "项目统计"
    APP_VERSION    = "1.0.5"
    APP_BUILD_DATE = "2026-10-03"
```

其它地方**一律不写死版本号**：

- 窗口标题 / 托盘标题：`ui/main_window.py` 里 `APP_TITLE = f"{APP_NAME} {APP_VERSION}"`
- 「关于」对话框：`版本：{APP_VERSION}（{APP_BUILD_DATE}）`
- exe 的 Windows 版本资源：`build.spec` 调用 `tools/version_info.py` 从 `app_info.py` 读取后生成
- 发布产物的文件名：`tools/make_release.py` 从 `app_info.py` 读取后拼出

> 历史教训：v1.0.5 之前 `build.spec` 没有 `version=` 参数，两个 exe 的
> FileVersion / ProductVersion / ProductName 全是空的，用户在资源管理器里分不清版本。

## 3. 版本标识检查清单

发版后按这个清单确认版本号确实"透"到了每一处：

- [ ] 启动日志首行：`Starting 项目统计 1.0.5`
- [ ] 主窗口标题：`项目统计 1.0.5`
- [ ] 「关于」对话框：`版本：1.0.5（2026-10-03）`
- [ ] exe 属性 → 详细信息：文件版本 `1.0.5.0`、产品版本 `1.0.5`、产品名称 `项目统计`
- [ ] 便携版 zip 文件名：`项目统计_v1.0.5_便携版.zip`
- [ ] 启动日志里的运行完整性：`Process integrity: medium (0x2000)`
      （出现 `low (0x1000)` 要先按 `README.md` 常见问题一节修目录标签，否则「打开目录」会被系统拒绝）

## 4. 目录与文件约定

| 路径 | 用途 |
| --- | --- |
| `project_stats/app_info.py` | 版本号唯一来源 |
| `CHANGELOG.md` | 逐版变更明细（新增/变更/修复/性能/已知问题），位于仓库根目录 |
| `docs/版本管理.md` | 本文档：规则、流程、版本记录表 |
| `docs/优化审查报告.md` | 代码审查结论与待办清单（1.1.0 的线索来源） |
| `docs/开发对话总结.md` | 2026-09-05 ~ 10-03 的开发过程纪要 |
| `requirements.txt` | 依赖版本锁定（换机器可复现环境） |
| `releases/` | **正式发布产物**：`项目统计_v<版本>_便携版.zip`、`项目统计_v<版本>_source.zip`、`SHA256SUMS.txt`、`manifest_v<版本>.json` |
| `backups/` | 开发过程中的源码快照：`项目统计_source_<阶段标签>_<yyyyMMdd_HHmmss>.zip`（内含 `MANIFEST.txt`），改动前/后各存一份；索引见 `backups/README.md` |
| `mockups/` | 设计稿与实现截图（`设计稿\`、`实现截图\`），索引见 `mockups/README.md` |
| `portable/dist/` | 当前构建的工作目录（会被下一次构建替换）；`dist_上一版_<时间>` 只保留最近一版，可回滚 |
| 远程仓库 | <https://github.com/YdaMooc/Porjetc-jz>（分支 `main`）：源码、文档、`backups/`、`mockups/` 与源码快照 zip 入库；`便携版 zip`（42.7 MB）与 `.venv/`、`portable/` 不入库 |

> 根目录只放：`README.md`、`CHANGELOG.md`、`requirements.txt`、`build.spec`、`.editorconfig`、
> `项目统计.ico` 与上述目录。文档一律进 `docs\`；发布产物一律进 `releases\`——
> `portable\` 下的东西都是"可重新生成"的中间产物，不要往里放唯一副本。
> 发布统一走 `tools\make_release.py`（旧的 `build.bat` 已于 2026-10-03 删除）。

## 5. 发布流程

```powershell
# 0. 确认工作区干净、程序没在运行（脚本会自动结束还在跑的 项目统计.exe）

# 1. 改版本号（唯一来源）
#    project_stats/app_info.py: APP_VERSION / APP_BUILD_DATE

# 2. 写 CHANGELOG.md 新一节 + 本文档第 6 节记录表

# 3. 打包发布（构建 → 替换 portable\dist → 生成 releases 下的产物与校验值）
.venv\Scripts\python.exe tools\make_release.py

# 4. 只重新打包、不重新构建（例如只想补一个 zip）
.venv\Scripts\python.exe tools\make_release.py --no-build

# 5. 冒烟验证：解压 releases 里的便携版 zip，双击 项目统计.exe，
#    确认标题栏版本号、关于对话框、"属性 → 详细信息"里的文件版本

# 6. 入库并推送（便携版 zip 被 .gitignore 排除，只推源码/文档/源码快照 zip）
git add -A
git commit -m "release: v<版本>"
git push origin main
```

`tools\make_release.py` 的设计要点是：**先构建到临时目录，成功后才替换 `portable\dist`**，
构建失败时上一版产物原样保留。（旧脚本 `build.bat` 是先删 `portable\` 再构建，构建失败会让
新旧产物一起消失；它已于 2026-10-03 随仓库整理删除，需要时从 `backups\` 源码快照里取回。）

## 7. 校验方式

```powershell
# 校验发布产物是否被改动过（在 releases 目录下执行）
cd releases
Get-FileHash .\*.zip -Algorithm SHA256 | Format-List
Get-Content .\SHA256SUMS.txt

# 查看 exe 的版本资源
(Get-Item '.\项目统计\项目统计.exe').VersionInfo | Format-List FileVersion, ProductVersion, ProductName, FileDescription
```

便携版使用方式：解压 `项目统计_v1.0.5_便携版.zip`，得到「项目统计」文件夹，
双击其中的 `项目统计.exe`。**exe 与同级 `_internal\` 必须一起拷贝**，缺一不可。
